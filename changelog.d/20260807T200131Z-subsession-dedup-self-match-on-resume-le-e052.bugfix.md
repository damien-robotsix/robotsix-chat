Fix subsession registry self-match dedup bug: when a periodic monitor with `dedup_key == checkpoint.ticket_id` was resumed after a container restart, `create()` would insert the entry first, then `find_active_periodic_by_ticket_id` would match the newly-inserted entry itself — raising `SubsessionDedupError` and leaving a RUNNING zombie with no worker task. Dedup checks now run before insertion.
