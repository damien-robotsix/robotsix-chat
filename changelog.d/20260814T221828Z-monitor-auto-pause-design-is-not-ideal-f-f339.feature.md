`spawn_subsession` and `spawn_subsession_tool` now accept an `auto_stop_no_change_runs` parameter that overrides, per periodic monitor, how many consecutive `NO_CHANGE` runs it tolerates before auto-closing. The value is validated (integer ≥ 1), persisted in the subsession checkpoint so it survives restart/resume, and falls back to the configured `subsessions.auto_stop_no_change_runs` default when not supplied.
