**Breaking (config):** Langfuse credentials move to the canonical component-standard block. `langfuse` is now `{host, projects}`, where `projects` maps a Langfuse **project name** to `{public_key, secret_key, project_id}` — this component declares `robotsix-chat` (main agent) and `robotsix-chat-cognee` (memory subsystem). The old single-project `langfuse.{public_key, secret_key}` fields and the whole `memory.langfuse` block are **removed**; `memory.langfuse_project` now names which project cognee's own LLM traffic traces to, and its credentials are resolved from the top-level block. One standard block per component is what lets central-deploy enumerate the fleet's Langfuse credentials uniformly and dispatch them to the consumers that need them (the chat trace proxy, cost-monitor's reconciliation) — previously every component invented its own layout and discovery silently found nothing. Per the repo's removed-field rule, both models strip the legacy keys in a `model_validator(mode="before")` and log a warning, so an upgraded image starts cleanly against a not-yet-migrated `config.json` instead of crash-looping on `extra="forbid"`; the old values are dropped rather than migrated, so such a deployment traces nothing and reports no projects until its config is rewritten.
