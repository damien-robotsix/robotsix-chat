`fleet_auth` is now a single top-level setting. It was declared three times — under `http_probe`, `render_url` and `public_fetch` — as three copies of the same `FleetAuthSettings`, so the one fleet reverse-proxy credential had to be entered in three places and three copies of `auth_hosts` kept in sync. The per-tool fields are removed outright, with no deprecation shim: move any values you have set to the top-level `fleet_auth`. This also matches what central-deploy already writes when it reconciles `fleet_auth.auth_hosts`, which previously produced a config chat rejected at boot.
