`list_repo_files` now accepts a `path` directory argument alongside `glob`. Every sibling repo-study tool (`read_repo_file`, `search_repo_files`, …) takes a `path`, so agents reach for it here too and were met with a hard `Additional properties are not allowed ('path' was unexpected)` validation failure — observed live twice in consecutive turns, wasting a turn each time and generating recurring `tool_error` tickets from the trace-review agent. A directory is simply a glob prefix, so it is now accepted directly and combines with `glob` when both are given.
