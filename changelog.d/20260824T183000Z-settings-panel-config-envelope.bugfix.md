Opening the Settings panel and pressing Save no longer resets the whole configuration to its defaults. The config endpoints returned the config document spread across the top level of the response, but the shared settings panel reads it from a `config` key and falls back to an empty document when that key is missing — so the form rendered every field at its schema default, and the first Save wrote those defaults over the live config. Secrets survived (they are masked and merged on write), but ports, hosts, feature flags and the operator's agent instruction were all reset. `GET /config`, `PUT /config`, `GET /config/versions`, `GET /config/versions/{version}` and `POST /config/rollback` now use the envelopes the fleet's config-ownership standard defines, and `PUT`/`rollback` answer with the new effective config so the panel re-renders from what was actually saved.
