Chat sessions now show which model they run on, and the agent can escalate a session to the frontier tier when it is genuinely stuck. Sessions start on the configured chat model (`opus`) and the agent calls `escalate_model(reason)` to pin that one conversation to `claude-fable-5` for the rest of its life; the switch takes effect on the next message. The session list and chat header display the active model, marking escalated sessions, and update live via a new `session_model` SSE frame.
