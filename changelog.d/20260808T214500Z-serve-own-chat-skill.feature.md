Chat now serves its own `GET /chat-skill` document. central-deploy's roster drops any component that does not serve a skill body, so chat was missing from its own roster and could not address itself through `component_request` — leaving the deploy plane's `PUT /chat/config/{name}` as its only route to its own config, which rebuilds the document from a stored schema template. The skill documents chat's own `/config` read, write, version-history and rollback endpoints.
